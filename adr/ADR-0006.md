# ADR-0006: Adopt CoreUI as the Design Reference and Re-Skin the Bespoke `vf-*` UI

**Status**: Accepted
**Date**: 2026-08-20
**Decision**: The constitution (v1.4.1, Principle IV) mandates CoreUI
(`https://github.com/coreui/coreui-free-bootstrap-admin-template.git`) as the
design reference. The shipped UI used a bespoke `vf-*` class system
(`tokens.css`/`theme.css`/`vf-sidebar`/`vf-topnav`). This ADR ratifies the
constitution: **adopt CoreUI as the design reference and re-skin the bespoke
UI to CoreUI/Bootstrap classes**, resolving GAP-002 (docs/analysis/GAP_REPORT.md
L22). The re-skin is presentation-only — page models, data, and server-side
pagination are unchanged (SPEC-0009).

## Context

- Constitution v1.4.1 Principle IV mandates CoreUI as the design reference
  (GAP-002, docs/analysis/GAP_REPORT.md L22–L32).
- The phase-2 UI shipped a bespoke system: `tokens.css`/`theme.css`/
  `bootstrap-icons.css` plus a `vf-sidebar`/`vf-topnav` shell with `vf-*`
  utility classes. No CoreUI assets existed in `wwwroot/` (AdminLTE removal was
  AC-008 in phase 2).
- SPEC-0009 (CoreUI UI foundation) defines the convergence: re-skin all pages
  to CoreUI classes while preserving behavior (page models, data, server-side
  pagination, `?page=N`).
- The legacy app is the functional specification; the re-skin must not change
  business behavior (library/01 deterministic rules).

## Decision

1. **CoreUI is the design reference.** All page presentation uses CoreUI/
   Bootstrap classes (`card`, `table table-striped table-hover`, `btn
   btn-primary`, `alert alert-*`, `badge text-bg-*`, `form-control`,
   `form-select`, `form-label`, `mb-3`, `text-end`, `d-inline`). The bespoke
   `vf-*` utility classes are removed from all 22 pages in `Areas/`.
2. **The shell keeps its structural wrappers.** `vf-shell`/`vf-main`/
   `vf-content`/`vf-skip-link` remain as structural (non-visual) wrappers,
   ported into `wwwroot/css/vf-component-styles.css` using `--cui-*` design
   tokens. `tokens.css` and `theme.css` are deleted (T077).
3. **No `_DataTable` for re-skinned pages.** Server-side pagination is
   preserved; the client-side `_DataTable` component is not used on Reporting
   pages (SPEC-0009, CoreUIPageRenderingTests).
4. **Component-based pages.** `Queries` → `_PublicQueryForm`, Notifications →
   `_InfoPage`; the component provides the page title (root `Pages/Index.cshtml`
   precedent).
5. **Auth pages** use `_AuthLayout` (centered auth card); public pages keep
   their own `<h1>`; `_PageHeader` is wired into the sidebar branch of
   `_Layout` only.

## Alternatives Considered

1. **Amend the constitution to ratify the bespoke system** — rejected: the
   constitution is the governing document and Principle IV is explicit; the
   bespoke system duplicated CoreUI functionality with no maintenance benefit.
2. **Full CoreUI template adoption (vendored assets + JS)** — rejected: the
   CoreUI template's demo JS (charts.js, widgets.js) and SCSS build chain are
   not needed; the design tokens and class conventions are adopted, demo assets
   are deleted (T085).
3. **Keep `vf-*` classes as aliases** — rejected: dual class systems double
   maintenance and confuse the class mapping; the mapping is one-way to CoreUI.

## Consequences

- All 22 pages in `Areas/` are re-skinned; no `vf-*` classes remain in
  `Areas/` (verified by grep, T078).
- `tokens.css`/`theme.css` and demo assets (charts.js, widgets.js, style.scss,
  simplebar.scss) are deleted; `wwwroot/lib/README.md` documents the remaining
  assets (T077/T085).
- Accessibility: validation-summary alerts declare `role="alert"`; form
  controls have labels; alerts declare `role="alert"`/`role="status"` (WCAG
  3.3.2/1.3.1/4.1.3, CoreUIAccessibilityTests).
- Behavior preserved: page models, data, and server-side pagination unchanged;
  functional tests stay green (256/257 with the known timing flake passing in
  isolation).
- Test coverage: 8 new suites (TS-001/002/003/005/006/008/009/012/013) —
  UnitTests 254/254, IntegrationTests 44/44 (T080).
