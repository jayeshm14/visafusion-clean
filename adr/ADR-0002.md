# ADR-0002: AI Environment Validation Gate Architecture

**Status**: Accepted
**Date**: 2026-08-06
**Decision**: Architecture for the AI Environment Validation feature (SPEC-0001) — a PowerShell validation script plus a GitHub Actions CI gate producing version-controlled report artifacts.

## Context

The VisaFusion program relies on a deterministic, AI-native engineering environment
defined across the `library/` standards and grounded in the live-verified `findings/`
reports. Claims that the 12 documented engineering integrations (GraphRAG, MCP, ADRs,
C4, DDD, Event Storming, Docs-as-Code, Backstage, OpenTelemetry, CodeQL, Dependabot,
NDepend) are integrated into the workflow must be verifiable against the authoritative
docs in `findings/` and `library/`. Without a repeatable validation, documentation can
drift from the intended workflow and the environment degrades into an unstructured
coding prompt.

Constitution Principle IV requires an ADR for every architectural decision; the
validation-gate architecture is such a decision. Principle V requires automated tests
and that the repository stays buildable and deployable.

## Decision

- **Validation script**: a PowerShell 5.1 script (`scripts/ai-environment-validation/validate-ai-environment.ps1`),
  compatible with PowerShell 7 (`pwsh`), using only built-in cmdlets
  (`Get-ChildItem`, `Select-String`, `ConvertTo-Json`, `ConvertFrom-Json`). It scans
  `findings/` and `library/` for the 12 integrations, applies the workflow-directive
  test (BR-002), classifies each as validated / partial / missing / contradictory, and
  records provenance (source file + line).
- **Integration registry**: a PowerShell data file (`scripts/ai-environment-validation/
  integrations.psd1`) holding the 12 integrations (id, name, canonical search terms,
  governing doc, constitution principle).
- **CI gate**: a GitHub Actions workflow (`.github/workflows/ai-environment-validation.yml`)
  triggered on changes to `findings/**` and `library/**` (FR-008). It runs the script
  and fails the check when the validation result is not `passed` (blocks merge).
- **On-demand runs**: the script is parameterized (`-SourceDirs`, `-OutputDir`,
  `-ReportOnly`) so the agent can run it ad hoc (FR-006).
- **Report artifacts**: version-controlled Markdown report (`report.md`) plus a
  machine-readable JSON summary (`summary.json`) under `reports/ai-environment-validation/`,
  conforming to the v1 contract in `contracts/validation-summary.md` (FR-007).
- **Tests**: Pester 5 unit tests (`tests/ai-environment-validation/
  validate-ai-environment.Tests.ps1`), written first (TDD) and run in CI.
- **Governance**: Knowledge Graph updated after the task (Principle IV); ADR-0002
  documents this decision.

## Alternatives Considered

1. **Python validation script** — rejected: adds a runtime dependency and diverges from
   the repository's PowerShell tooling convention (`.specify/scripts/powershell/*.ps1`).
2. **Node.js script** — rejected: same dependency drawback; no existing Node tooling in
   the repo.
3. **Pure GitHub Actions YAML with shell steps** — rejected: harder to unit-test and
   reuse on demand; a dedicated script is testable with Pester and runnable locally.
4. **Manual / agent-only validation (no CI gate)** — rejected: not repeatable or
   enforceable; violates the merge-blocking quality gate (Principle V).

## Consequences

- The validation is repeatable, deterministic, and enforceable as a merge gate.
- The JSON summary is machine-readable, enabling the CI gate and the Knowledge Graph to
  consume the status programmatically.
- The report artifacts are version-controlled and PR-reviewed (Docs-as-Code, `library/06`).
- The script and workflow are the single source of truth for environment validation;
  changes to the contract require a schema version bump and a new ADR.
