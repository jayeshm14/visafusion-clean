# ADR-0004: Migration CLI — Out-of-Order Step Fails Fast with Logged Exit 1

**Status**: Accepted
**Date**: 2026-08-09
**Decision**: The VisaFusion migration CLI (`VisaFusion.Migration`) must never exit
silently. An out-of-order or unknown `--step` raises `PreflightException` (exit 1) with
a precise message, and the static Serilog logger must remain usable in the top-level
catch/finally of `Program.cs` regardless of DI provider disposal.

## Context

Found during Definition-of-Done deep verification of SPEC-0004 (feature 004). With the
legacy `VisaEntry` → target `VisaFusion` migration at `preflight;snapshot;schema`
completed and `copy` blocked on GAP-0002, running:

```
VisaFusion.Migration.exe --step validate
VisaFusion.Migration.exe --step cleanse
VisaFusion.Migration.exe --step identity
```

exited **2 (StepFailure) with zero log output** — neither a `[FTL]` line on console nor
in the file sink. `contracts/migration-cli.md` §2 requires "a step may not run before its
predecessor completes successfully"; §4 defines exit 1 as Preflight failure. Two defects
combined:

1. `Program.cs` registered Serilog with `services.AddLogging(b => b.AddSerilog(dispose: true))`.
   The `StepRunner` predecessor check threw `PreflightException` from **outside** its own
   try block. During stack unwinding the `using var provider` disposed the shared static
   `Log.Logger` **before** `Program.cs`'s `catch (Exception)` executed `Log.Fatal` — so
   the exception was swallowed and the process returned exit 2 with no diagnostics
   (NFR-006 violation).
2. The predecessor check was placed before the `try`, so the exception never reached the
   runner's `catch (PreflightException)` → exit-1 path; it fell through to the generic
   `catch (Exception)` → exit-2 path instead, misclassifying an order violation as a
   step failure.

## Decision

1. **Logger ownership**: `AddLogging(b => b.AddSerilog(dispose: false))`. The DI
   container no longer disposes the static `Log.Logger`; `Log.CloseAndFlush()` in
   `Program.cs`'s `finally` is the single lifecycle owner (NFR-006). The static logger is
   then usable in the outer `catch` even after provider disposal during unwinding.
2. **Pure, unit-testable guard**: extract the single-step validation into
   `StepRunner.EnsureRequestedStepIsRunnable(requestedStep, runState, registeredSteps)` —
   a public static method that throws `PreflightException` for (a) unknown steps and
   (b) steps whose predecessor has not completed. `RunAsync` invokes it inside the try
   block so the existing `catch (PreflightException)` maps it to exit 1 with the
   "Preflight failure: …" message.
3. **Exit code semantics**: unknown step or out-of-order step → exit **1** (Preflight
   failure), consistent with the exception type and the §2 "may not run" precondition.
   Genuine step execution failures (e.g. GAP-0002 data-quality gap) remain exit **2**.
4. **Regression coverage**: `tests/UnitTests/StepRunnerPredecessorTests.cs` — pure unit
   tests (no database) covering null/full-run, unknown step, first-missing-predecessor
   naming, and runnable-when-complete.

## Alternatives Considered

1. **Move only the predecessor check into the try (no logging change)** — rejected: the
   FTL line still would not print because the provider (and the static logger) is disposed
   during unwinding before the outer catch executes. The silent-exit defect persists.
2. **Keep `dispose: true` and log via a captured `ILogger<Program>` instance** — rejected:
   a captured instance is disposed with the provider; the top-level catch/finally must be
   authoritative and independent of DI lifetime.
3. **Exit 2 for order violations** (previous behavior) — rejected: an order violation is a
   precondition failure of the §2 contract, not a step execution failure; §4's exit-1
   category ("preflight") is the correct classification, and it was already the intended
   semantics of the `PreflightException` type.

## Consequences

- Operator-facing: out-of-order `--step` now prints `Preflight failure: Step 'validate'
  requires 'copy' to complete first (fixed order).` and exits 1; unknown steps print
  `Preflight failure: Unknown step '…' (contracts/migration-cli.md §2).` and exit 1.
- No silent exits remain in the CLI contract path (verified: `preflight` exit 1 on missing
  backup, `copy` exit 2 on GAP-0002, `schema` exit 0, `validate/cleanse/identity` exit 1
  out-of-order, unknown step exit 1).
- Full test suite stays green: 9 integration + 20 unit (incl. 8 new) + 22 functional.
- ADR-0003 (migration tooling, task T052) remains **pending**; this ADR does not
  substitute for it.
